# 🔀 The Important Part: Team Routing

You said:

> "the labs should not be together for any team"

I would interpret this as **the two coding/lab stations must be separated**.

So instead of:

**Team A:** Coding 1 → Coding 2 → Logic → Puzzle...

we create different routes.

For example:

### Team 01

`Coding A → Puzzle A → Riddle A → Logic B → Mystery A → Coding B → ...`

### Team 02

`Logic A → Mystery B → Coding A → Riddle B → Puzzle A → Coding B → ...`

### Team 03

`Puzzle B → Coding B → Logic A → Mystery A → Coding A → ...`

This prevents **40 teams from reaching the same station simultaneously**.

---

# ⏱️ Coding Lab – 5 Minute System

This needs to be very controlled.

When a team reaches the coding station:

### Step 1

They scan the station QR / enter station code.

Website checks:

> Is this team supposed to be at Coding A now?

If **YES** → Start.

If **NO** → ❌ "Wrong Station."

### Step 2

A **5:00 countdown** starts.

Example:

**CODING CHALLENGE A**

`05:00`

`04:59`

`04:58`

...

### Step 3

Team submits the answer/code.

The system records:

* Team ID
* Challenge ID
* Start time
* Submission time
* Completion time
* Correct/incorrect
* Attempts

### Step 4

At exactly **00:00**, the challenge automatically closes.

No extra time.

---

# 🏆 Scoring

I recommend **two separate things**:

### 1. Challenge Score

Each challenge gives points.

For example:

* Correct first attempt → **100 points**
* Correct second attempt → **80 points**
* Incorrect → **0 points**

You can customize this.

### 2. Time

The website also records the **exact completion time**.

So leaderboard ranking can be:

> **Total Score → Total Completion Time → Number of Attempts**

This is much fairer than simply saying "first team wins."

# 📍 Station Verification

This is very important.

Each physical station gets a unique QR code.

For example:

```text
CODING-A
QR-A001
```

Team reaches the location → scans QR.

The server checks:

```text
Team 017
        ↓
Expected Station = CODING-A
        ↓
QR = CODING-A
        ↓
✅ ACCESS GRANTED
```

Wrong station:

```text
Expected: PUZZLE-A
Scanned: CODING-A

❌ WRONG LOCATION
```

This prevents teams from randomly jumping ahead.

# 🚦 Preventing Crowd Problems

With **36–40 teams**, this is the biggest issue.

You don't want:

> 15 teams standing outside Coding A.

So we should create **route groups**.

For example:

### Group A

Teams 01–08

### Group B

Teams 09–16

### Group C

Teams 17–24

### Group D

Teams 25–32

### Group E

Teams 33–40

Each group gets different starting stations and different routes.

And critically:

**Coding A and Coding B are never consecutive in any team's route.**

### One important recommendation

**Don't let participants choose their next challenge.** The backend should generate and control each team's route.

That gives you three major benefits:

1. **No crowding**
2. **No skipping challenges**
3. **Fair timing and scoring**

And because your coding labs have a strict **5-minute timer**, I'd make those stations **server-controlled**, not browser-controlled, so refreshing the page doesn't reset the timer.
